## Current status

- **Last completed**: **Phase 3 stage 4 — the semantic engine** (branch `feat/ph3-semantic-analysis`, PR pending): `tempr_intel::SemanticEngine` walks the editor's tree-sitter tree per statement and produces the spec §5.1 model — `Analysis { scopes, diagnostics }` where each `Scope` carries the region's `WITH` CTEs, its relation bindings (aliases, catalog-resolved columns as arena indices, CTE/FROM-subquery columns as derived `Local` names), and child subtree scopes; every `field` reference resolves bare / `qualifier.col` / `schema.rel.col` (CTEs shadow relations on the unqualified path; catalog does exact-then-unique-folded), and the engine reports `UnknownRelation`/`UnknownColumn` as errors plus `AmbiguousColumn` as the one warning kind (spec decision 8). Grammar findings from the §9 probe are baked into the walk: a two-phase read per region (bindings collected without analyzing subquery bodies, then bodies analyzed with the complete frame, so clause order cannot mislead visibility), `set_operation` statements scope per `select` side (merging sides would invent ambiguity the server doesn't see), CTE bodies see only earlier CTEs (`WITH RECURSIVE` self-references stay silent over their columnless bindings), `ERROR` fragments become `SyntaxError` diagnostics and suppress semantic ones over their ranges, and the no-catalog silence rule passes with an empty cache (only syntax diagnostics may appear). Caching: per-`SqlFileId` `Arc<Analysis>` validated by the new process-unique `Buffer::revision` — integer compare on the request path; `set_catalog` swaps the cache reference and resets analyses. Plan deviations for the record: stage-4 tasks 3–4 (scope walk, resolution) landed as one feat commit — the walk and its resolution are one compile unit whose §8 test table forced the set-operation restructure mid-task; the spec's "analyze takes `&Buffer`" became `&mut Buffer` (Buffer's lazy reparse needs `&mut`) and the spec's "cache validated by EditId" became `Buffer::revision` (undo restores an earlier text state while reusing ids), both recorded in decisions and docs/12-sql-intelligence.md. A code-review pass on the PR then fixed seven issues the shipped walk had: regions are now their **container nodes** (grammar keeps `select`/`from`/`where` as siblings, so the old `unwrap_subquery`-to-`select` walk dropped every subquery and set-op-side binding), derived-table column lists actually derive (FROM/lateral subqueries), the `DELETE` target binds from the statement-level `from` sibling, `lateral_cross_join`/function items bind their alias, `diagnostics_in` stops returning diagnostics that end before the query, column qualifiers follow PostgreSQL (an alias hides the relation name; a schema is never a two-part qualifier), and bare-column resolution is nearest-scope-first (no cross-level ambiguity). Revisions now come from a process-wide counter, so a reopened buffer cannot hit the previous instance's cached analysis.

| 2026-10-21 | Phase 3 | Code-review pass on PR #19 (stage 4): verified each finding against the pinned grammar with a scratch probe, then fixed seven issues. (1) **Region boundary** — `unwrap_subquery` was returning the `select` node, but the grammar keeps `select`/`from`/`where` as siblings, so subquery and set-operation-side scopes had no bindings and no predicates (e.g. `where exists (select o.zz from orders o)` reported `UnknownRelation o` on valid SQL; set-op sides missed `zz`). Regions are now the container node (`statement`/`subquery`/`set_operation`), set-op sides are split per `select` + following clause siblings, and a parenthesized nested side becomes its own scope.
