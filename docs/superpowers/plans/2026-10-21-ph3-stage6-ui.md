# Phase 3 Stage 6 — Intelligence UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Wire the shipped intelligence model into the running app: `BufferChanged` publisher, `IntelligenceService` (engine owner, catalog subscriber, debounced background analysis), caret-anchored completion popup, diagnostic underlines + navigation, hover card, schema-refresh commands, and the key catalog entries for all of it.

**Architecture:** The `Buffer` stays owned by `EditorView` (D21: the buffer is a pure model; its owner publishes). The view calls the service for the two synchronous, per-keystroke paths (completion, hover — spec §2 decision 7), and hands the service an immutable text snapshot after a 100 ms idle debounce for diagnostics. `IntelligenceService` (in `tempr_services`) owns `Arc<SemanticEngine>`, mirrors each file's text into its own `Buffer` on a background task, caches `(source revision → Arc<Analysis>)`, and publishes `DiagnosticsReady`. It also consumes `ConnectionStateChanged` (load `.tcat`, then incremental refresh) and `SchemaRefreshed` (rebuild `CatalogCache` + `set_catalog`). The popup and hover card are rendered by `EditorView` itself, absolutely positioned from the primary cursor's painted line layout, so no extra window-level coordinate assumptions are needed.

**Tech Stack:** Rust 1.97.1, GPUI `ed8d600` (pinned), `tempr_editor::Buffer`, `tempr_intel` (`SemanticEngine`, `CatalogCache`, `Analysis`, `CompletionItem`), `tempr_services::{IntelligenceService, SchemaService}`, `tempr_events`.

**Spec:** [2026-09-07-phase3-sql-intelligence-design.md](../specs/2026-09-07-phase3-sql-intelligence-design.md) §5.3 (hover), §6 (service + UI, commands), §7 (error handling), §9 stage 6; [12-sql-intelligence.md](../../12-sql-intelligence.md) (HoverInfo shape); [11-gpui.md](../../11-gpui.md) (component + command rules).

## Global Constraints

- **Branch, PR, review — never commit to main.** Branch: `feat/ph3-intelligence-ui`.
- **Every task ends green**: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- **No new third-party dependencies.**
- **No I/O or DB query on the request path.** Completion and hover are synchronous over the engine's cached catalog and analysis.
- **No blocking the UI thread.** Diagnostics analysis runs on tokio over a text snapshot; the view only copies the text once per debounce window (100 ms idle, revision-checked).
- **No business logic in the UI.** The view calls the service, renders returned model types, and emits events; scope resolution, diagnostics and hover contents come from `tempr_intel`.
- **Every user action has a keybinding** (`core_commands()` is still the only catalog; the audit test is extended).
- **No mouse-only features.** Popup navigation/accept/dismiss and hover are all keyed.
- **Completion bindings must not leak when the popup is closed**: they use the `Editor Completion` context, added to the editor's key context only while the popup is open. GPUI resolves bindings by context depth (`bindings_for_input` sorts by `depth_b`), so `completion::Accept` outranks `editor::Newline` while open and disappears when closed.
- Canonical names: `IntelligenceService`, `HoverInfo`, `DiagnosticsReady`, `CompletionPopup`, `TriggerCompletion`, `NextDiagnostic`, `PrevDiagnostic`.
- No unwrap/expect in library code; tests may.

## Task 0 (done): GPUI integration probe

Read against the pinned gpui rev (`ed8d600`), not assumptions:

- `Keymap::bindings_for_input` sorts matching bindings by **context depth** (deeper context wins), then later registration. `Editor` + `Completion` is deeper than `Editor`, so completion's `enter`/`tab`/`escape` win only while the popup adds the second context. No `!Completion` predicate is needed.
- `TextRun.underline: Option<UnderlineStyle>` (`thickness`, `color`, `wavy`) — diagnostics can be painted by extending the existing per-byte run builder, not a second overlay.
- `Div::on_children_prepainted(Vec<Bounds<Pixels>>, …)` reports child bounds in **window** coordinates; the editor root's single child is the line list, so one stored `Bounds` gives the local origin for an absolutely-positioned popup.
- `AsyncApp::background_executor().timer(Duration)` exists — the debounce needs no new dependency.
- `gpui_compat::spawn_tokio` takes `&App`; `Context<T>` derefs to it, so a view can launch the service's async analysis.

→ Decisions: popup + hover card rendered inside `EditorView` (`absolute`), diagnostics underlines via `TextRun`, debounce in the view (it owns the buffer), analysis in the service.

## Task 1: Hover engine

- [ ] `hover.rs` model:
  ```rust
  pub struct HoverInfo { pub contents: String, pub range: Range<usize> }
  ```
- [ ] Word scan at an offset: identifier chars (`[A-Za-z0-9_$]`), quoted identifiers, plus the dotted qualifier path before it (reuse the completion lexer's `qualifier_before`/identifier rules via `pub(crate)`).
- [ ] Resolution, in order:
  - qualifier binding + column → column type/nullability/default/owner; `Local` columns use their carried type
  - path `schema.relation.column` → catalog column
  - bare word matching a visible binding or a catalog relation (unambiguous folded lookup) → relation card: kind, `schema.name`, estimated rows for tables, view `definition`, column list (`name type not null`)
  - bare word matching a schema → relation list
  - function name → signature (`name(args) → ret`)
  - nothing → `None`
- [ ] Contents are plain text with `\n` (the card renders it as lines; markdown can come with the theme system later).
- [ ] `SemanticEngine::hover(&self, file, buffer: &mut Buffer, offset) -> Option<HoverInfo>` uses the cached analysis (same `analyze` call).
- [ ] Tests: qualified column, bare unique column, table vs view card, function signature, schema card, local (CTE) column, no-catalog `None`, offset on whitespace/punctuation `None`, cursor inside the word vs at its end.
- [ ] Green → commit `feat(intel): hover resolution over the analysis and catalog`.

## Task 3: `IntelligenceService`

- [ ] `tempr_services` depends on `tempr_intel` (and therefore `tempr_editor` transitively).
- [ ] Fields: `bus`, `schema: Arc<SchemaService>`, `engine: Arc<SemanticEngine>`, `analyses: RwLock<HashMap<SqlFileId, Stored>>` (`{ source_revision, analysis }`), `active_connection: RwLock<Option<ConnectionId>>`, `subscriptions`, tokio `handle: RwLock<Option<Handle>>`.
- [ ] `new(bus, schema) -> Arc<Self>` with an empty `CatalogCache`; subscribe to `SchemaRefreshed` + `ConnectionStateChanged` via `Weak<Self>` (no cycle), keep the `Subscription`s alive.
- [ ] `Service::start` stores `Handle::try_current()`; `stop` clears subscriptions and analyses.
- [ ] `SchemaRefreshed` → read `schema.snapshot(connection)`, verify `snapshot.id`, build `CatalogCache::from_snapshot`, `engine.set_catalog`.
- [ ] `ConnectionStateChanged{Connected}` → background task: `schema.load_cached(id)`; if a snapshot exists, build the catalog immediately (this is the offline path — a cache load publishes no event); then `schema.refresh_incremental(id)` best-effort; publish `SchemaRefreshFailed` on error.
- [ ] `pub fn complete(&self, buffer: &mut Buffer, offset, explicit) -> Vec<CompletionItem>` and `pub fn hover(&self, buffer: &mut Buffer, offset) -> Option<HoverInfo>` — direct engine delegation (synchronous, UI thread, no I/O).
- [ ] `pub async fn analyze(&self, file, source_revision, text)` — build/update a mirror `Buffer` (minimal common-prefix/suffix replacement), `engine.analyze`, store `(source_revision, Arc<Analysis>)`, publish `DiagnosticsReady { file }`.
- [ ] `pub fn analysis(&self, file, source_revision) -> Option<Arc<Analysis>>` — exact revision only.
- [ ] Tests: completion/hover delegate with a synthetic catalog; analysis stores only for the matching revision; stale revision returns `None`; a `SchemaRefreshed` publish swaps the engine catalog; `DiagnosticsReady` is published once per analysis; `ConnectionStateChanged` failure publishes `SchemaRefreshFailed` (fake schema service with no pool).
- [ ] Green → commit `feat(services): IntelligenceService owns the engine, catalog and diagnostics`.

## Task 6: Editor integration

- [ ] **Publisher.** Every edit batch (`apply`, `insert_text`, `set_text`, undo/redo, IME replace, accept) emits `EditorEvent::Changed`, schedules debounced analysis, and closes/refreshes the popup as appropriate. `MainWindow` publishes `AppEvent::BufferChanged { file }` on `Changed`.
- [ ] **Analysis.** Debounce: `cx.spawn` + `background_executor().timer(100 ms)`; on wake, compare `buffer.revision()` with the captured revision, copy the text only if still current, then `gpui_compat::spawn_tokio(cx, service.analyze(...))`. Store `(revision, Arc<Analysis>)` when the result arrives (`UiEvent::DiagnosticsReady`).
- [ ] **Underlines.** `runs_for_line` tracks a `(color, underline)` pair per byte: error underlines solid `theme::ERROR`, warnings wavy `theme::WARNING`. Only visible diagnostics are collected per frame.
- [ ] **Completion popup.** Caret-anchored, `uniform_list`, max 12 rows, label + kind + detail; auto-open on an identifier character or a qualifier dot, `ctrl-space` explicit; typing re-filters; accept replaces `item.replace` with `item.insert` and places the cursor after it; dismiss/escape; selection scrolls into view.
- [ ] **Hover card.** `editor::Hover` resolves at the primary cursor; when there is no hover, the diagnostic message under the cursor is shown instead; a notice when neither exists. Any edit/motion closes the card.
- [ ] **Diagnostics navigation.** `f8`/`shift-f8` walk `next_diagnostic`/`previous_diagnostic`, wrap at the ends, move the cursor to `range.start`, and show the message card.
- [ ] **Status.** `MainWindow` renders `N errors · M warnings` beside the status line after `DiagnosticsReady`.
- [ ] **Schema commands.** Spawn the refresh on tokio; status reports object counts or the error; `RefreshIncremental` reports the `RefreshPath`.
- [ ] Tests (pure): `Analysis` previous-diagnostic ordering/wrap; completion accept range math helper; `diagnostics_summary` pluralization; no GPUI render tests (headless UI is not part of the harness).
- [ ] Green → commit `feat(ui): completion popup, diagnostic underlines, hover and intelligence commands`.
